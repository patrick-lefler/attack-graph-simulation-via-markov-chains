Multi-Stage Attack Graph Simulation Via Markov Chains: how far the results move when the inputs change, and what the model cannot show

The closed-form results on The Model are exact for one assumed transition matrix. This page asks where a control change has the most leverage, how much the results move when the transition probabilities are uncertain, and whether the solver code is correct. It ends with the model’s limitations and the data a calibrated version would need.

One-Row-at-a-Time Control Sensitivity

To ask where a control change has the most leverage, the comparison must change one row at a time and hold the starting stage fixed. Starting from S1 (so every row lies on the attacker’s path), the analysis applies two changes to each row separately: (a) a standardized shift of 0.05 of probability from the row’s largest non-self, non-A1 edge to A1, and (b) replacing that row with its improved-posture row.

Display code 
harden_one_row <- function(P, i, delta = 0.05) {
  donor <- unname(which.max(replace(P[i, ], c(i, 7), 0)))
  P[i, donor] <- P[i, donor] - delta
  P[i, 7] <- P[i, 7] + delta
  list(P = P, donor = all_state_names[donor])
}

outcomes_from_s1 <- function(P) {

  c(cont = B[1, 1], cat = B[1, 2] + B[1, 3])
}

How to read the table. Each row tests one change to the defenses at a single stage, holding everything else fixed, for attacks that start at S1. The first approach moves a fixed 0.05 of probability from the attacker’s most likely next move to containment; the donor column names that move. What the table tells you. Under the fixed shift, improving S2 gives the largest containment gain, 2.25 points, against 2.12 for S1, and the gains shrink for deeper stages. Early-stage defenses therefore carry somewhat more leverage, but the differences are modest, and the checks further down this page show that the order of S1 and S2 is not reliable. The values come from assumed inputs, not measured control effects.

In more detail

Under these illustrative parameters, the largest standardized containment gain from S1 comes from changing the S2: Initial Foothold row (2.25 pp), not S1 itself (2.12 pp). Gains decline for deeper rows, to 1.43 pp at S6, which is 36% below the best row. Under this standardized shift the gradient looks moderate (the best row is about 1.6 times the last). The next table shows that this depends on how the perturbation is defined, and the ranking check in Parameter Uncertainty shows that the order of the top two rows is not stable. Two caveats: the 0.05 shift is a different relative change in each row, and the table only covers attacks that start at S1. The ranking reflects the hand-set parameters.

Why the ranking looks this way. For a small shift \(\varepsilon\) from edge \((i, j)\) to A1, the change in containment from S1 is approximately

\[\Delta B_{1,A1} \approx \varepsilon \, N_{1i} \, \bigl(1 - B_{j,A1}\bigr)\]

That is, expected visits to row \(i\) times the catastrophic share of the donor state \(j\). The table below confirms that the identity reproduces the standardized-shift column. The modest gradient is the product of two opposing trends: visits fall with depth while the donor’s catastrophic share rises. It also depends on the perturbation design.

harden_one_row_prop <- function(P, i, rel = 0.10) {
  inc <- rel * P[i, t_dim + 1]
  others <- setdiff(which(P[i, ] > 0), c(i, t_dim + 1))
  P[i, others] <- P[i, others] - inc * P[i, others] / sum(P[i, others])
  P[i, t_dim + 1] <- P[i, t_dim + 1] + inc
  P
}

How to read the table. Each row is one stage whose defenses are improved, for attacks starting at S1. Expected visits is how often an attack passes through that stage on average. The donor share is the chance that an attack at the stage it would otherwise have moved to ends in catastrophe. Multiplying the two by the 0.05 shift gives a predicted gain, shown next to the actual gain. The last column repeats the exercise with a 10% proportional improvement instead.

What the table tells you. The prediction matches the actual gain in every row, so the ranking is explained by two opposing forces: early stages are visited more often, but attacks moving on from them are less likely to end badly. Because these roughly offset, the gains differ only modestly. Under a proportional improvement, the gap between the first and last stages grows from about 1.6 times to 4.0 times, so the answer depends on how an improvement is defined.

The gradient depends on the perturbation. Under a proportional perturbation (+10% relative A1 probability, taken pro rata from the other exits), the upstream-to-downstream ratio is about 4.0× rather than 1.6×. A defensible ranking needs a control-to-parameter mapping, ideally expressed as hazard ratios on rates. A fixed absolute shift is not enough.

Parameter Uncertainty (Dirichlet)

Closed-form results are exact only given \(P\), and \(P\) is uncertain. To quantify that, each transient row is treated as Dirichlet(\(\alpha \cdot p_{\text{row}}\)) over its non-zero entries (structural zeros stay zero), with concentration \(\alpha = 50\) as a stand-in for “moderate confidence” in the elicited values. The solver is re-run on 5,000 sampled matrices per regime.

Display code 
draw_P <- function(P, alpha) {
  for (i in seq_len(t_dim)) {
    idx <- which(P[i, ] > 0)
    g <- rgamma(length(idx), shape = alpha * P[i, idx])
    P[i, idx] <- g / sum(g)
  }
  P
}

summarise_draw <- function(P) {
  sol <- solve_absorbing_markov(P[1:t_dim, 1:t_dim], P[1:t_dim, 7:9], step_hours)
  tibble(Stage = transient_names, cont = sol$B[, 1], cat = sol$B[, 2] + sol$B[, 3], hours = sol$hours)
}
alpha_conc <- params$dirichlet$alpha_conc$value
n_draws <- params$dirichlet$n_draws$value

The improved posture beats the baseline in nearly every rerun, but that check is weak by design, because its matrix was built to be better. The improved-posture comparison draws baseline and improved matrices independently, so the last column checks whether the improvement survives parameter noise, not a paired control effect. The paired comparison below estimates the scenario effect directly.

In more detail

The S3 crossing is fairly, not fully, stable. In 63.7% of draws, catastrophic outcomes first become more likely than containment at S3 (the baseline point estimate); the remaining draws place the crossing at other stages (shares: S2 2.6%; S3 63.7%; S4 32.8%; S5 1.0%). The statement “S3 is the tipping point” is therefore conditional on these parameters and on the assumed concentration \(\alpha\); the α sweep below shows that α changes the location of the crossing, not just the interval widths.

Uncertainty is substantial for the point estimates. At S3 the 90% interval for catastrophic probability is 42.3% to 63.5%, around the point estimate of 52.9%.

The improved posture is better in almost every draw, which says little by itself. The improved posture has higher containment than the baseline in at least 99.9% of draws at every stage. The improved matrix was built to have higher A1 probabilities, and the two regimes are drawn independently, so this check is weak. The paired comparison below gives the size of the difference with an interval.

Correlated Detection Quality Across Stages

Display code 
shared_sd_log <- params$dirichlet$shared_sd_log$value
set.seed(seed)
shared_cat_s1 <- map_dbl(seq_len(n_draws), \(d) {
  P <- draw_P(P_baseline_raw, alpha_conc)
  f <- exp(rnorm(1, 0, shared_sd_log))
  for (i in seq_len(t_dim)) {
    a_new <- min(P[i, t_dim + 1] * f, 0.95)
    others <- setdiff(seq_len(ncol(P)), t_dim + 1)
    P[i, others] <- P[i, others] * (1 - a_new) / (1 - P[i, t_dim + 1])
    P[i, t_dim + 1] <- a_new
  }
  stopifnot(abs(sum(P[1:t_dim, ]) - t_dim) < 1e-8)
  outcomes_from_s1(P)["cat"]
})
indep_cat_s1 <- draws |> filter(Stage == transient_names[1]) |> pull(cat_b)
shared_int <- quantile(shared_cat_s1, c(0.05, 0.95))
indep_int <- quantile(indep_cat_s1, c(0.05, 0.95))

Correlated detection quality widens the intervals. The analysis above draws each row independently, which lets errors cancel along the attack path. Detection quality is an organizational capability: a SOC that is weak at S2 is probably weak at S3 and S4 too. Multiplying every row’s A1 probability by a common log-normal factor (log-scale SD 0.35) widens the 90% interval for catastrophic probability from S1 from 19.8%–36.0% to 7.0%–51.3%.

Paired Improvement Effect

Display code 
# Common random numbers: the same uniforms drive both regimes' gamma draws
draw_pair <- function(Pb, Ph, alpha) {
  for (i in seq_len(t_dim)) {
    idx <- which(Pb[i, ] > 0 | Ph[i, ] > 0)
    u <- runif(length(idx))
    gb <- qgamma(u, shape = pmax(alpha * Pb[i, idx], 1e-8))
    gh <- qgamma(u, shape = pmax(alpha * Ph[i, idx], 1e-8))
    Pb[i, idx] <- gb / sum(gb)
    Ph[i, idx] <- gh / sum(gh)
  }
  list(b = Pb, h = Ph)
}
set.seed(seed)
paired <- map(seq_len(n_draws), \(d) {

Robustness of the One-Row Ranking

Display code 
shift_cont_from_s1 <- function(P, i, delta = 0.05) {
  donor <- unname(which.max(replace(P[i, ], c(i, t_dim + 1), 0)))
  if (P[i, donor] < delta) return(NA_real_)
  P2 <- P
  P2[i, donor] <- P2[i, donor] - delta
  P2[i, t_dim + 1] <- P2[i, t_dim + 1] + delta
  outcomes_from_s1(P2)["cont"] - outcomes_from_s1(P)["cont"]
}

The one-row ranking is not robust. Repeating the standardized 0.05 shift on 2,000 Dirichlet draws, the S2 row gives the largest containment gain from S1 in 61.9% of draws and the S1 row in 31.6%; S2 beats S1 in 65.7% of draws. The defensible statement is that the S1 and S2 rows carry the most leverage, not that one of them ranks first.

Limitations and Future Work

The model’s structural assumptions are listed under Parameterization and Assumptions, and the sections above show how sensitive the results are to the elicited inputs. This section covers the data a richer, calibrated version would need.

Future work: real-world data sources

The current model uses none of the following sources. They describe network and identity topology, which tells a richer model which edges exist. They do not by themselves supply the transition probabilities or timing this model needs (see the calibration note after the table).

Network Telemetry & Flow Logs: Real connection edges and service dependencies come from VPC Flow Logs (AWS/Azure/GCP), Zeek/Corelight network analysis sensors, and NetFlow/IPFIX from core network routers and firewalls.

Service Dependency & Configuration Management Databases (CMDB): Service-to-service call maps are extracted from application performance monitoring tools (e.g., Datadog, Dynatrace), service mesh registries (e.g., Istio, Envoy), and enterprise CMDBs (e.g., ServiceNow).

Vulnerability Management & Posture Assessment Scanners: CVSS scores, exploit metrics, and missing patches are pulled via API from enterprise vulnerability scanners such as Tenable Nessus, Qualys, Rapid7 InsightVM, or cloud posture platforms (Wiz, Prisma Cloud).

Active Directory & Identity Access Graphs: Identity edges and lateral movement pathways are exported from tools like BloodHound Enterprise, Microsoft Entra ID, and Okta Access Graph logs.

Calibration Data and Survival-Analysis Pitfalls

The parameters of this model are stage-transition probabilities and stage durations. Estimating them requires timestamped transitions rather than topology:

  • Internal incident-response timelines and EDR or SIEM alert timestamps mapped to MITRE ATT&CK tactics.
  • Purple-team and breach-and-attack-simulation results (time to detect per technique).
  • The VERIS Community Database, whose timeline fields record initial compromise, exfiltration, discovery, and containment in coarse units (VERIS Framework).
  • Public benchmarks as priors: M-Trends, the Sophos Active Adversary Report, and CrowdStrike breakout times.

Fitting these data raises standard survival-analysis issues:

  • Right censoring: incidents still open at data extraction.
  • Interval censoring: stage entry is known only to a window, or to a unit such as “days.”
  • Left truncation and detection-dependent selection: only detected intrusions are recorded.
  • Competing risks: containment censors progression, so naive Kaplan–Meier estimates of time to catastrophe are biased, and Aalen–Johansen estimators are appropriate.
  • Unobserved heterogeneity: attacker types differ, for example fast eCrime affiliates versus slow espionage actors.

Multi-state packages such as msm, mstate, and flexsurv handle these directly.

## One-Row-at-a-Time Control Sensitivity {#one-row-at-a-time-control-sensitivity}

To ask where a control change has the most leverage, the comparison must change **one row at a time** and hold the starting stage fixed. Starting from S1 (so every row lies on the attacker's path), the analysis applies two changes to each row separately: (a) a standardized shift of 0.05 of probability from the row's largest non-self, non-A1 edge to A1, and (b) replacing that row with its improved-posture row.

**How to read the table.** Each row tests one change to the defenses at a single stage, holding everything else fixed, for attacks that start at S1. The first approach moves a fixed 0.05 of probability from the attacker's most likely next move to containment; the donor column names that move. **What the table tells you.** Under the fixed shift, improving `r sub(":.*", "", transient_names[best_row])` gives the largest containment gain, `r sprintf("%.2f", 100 * sens_df$Shift_Cont[best_row])` points, against `r sprintf("%.2f", 100 * sens_df$Shift_Cont[1])` for S1, and the gains shrink for deeper stages. Early-stage defenses therefore carry somewhat more leverage, but the differences are modest, and the checks further down this page show that the order of S1 and S2 is not reliable. **In more detail**

Under these illustrative parameters, the largest standardized containment gain from S1 comes from changing the **`r transient_names[best_row]`** row (`r sprintf("%.2f", 100 * sens_df$Shift_Cont[best_row])` pp), not S1 itself (`r sprintf("%.2f", 100 * sens_df$Shift_Cont[1])` pp). Gains decline for deeper rows, to `r sprintf("%.2f", 100 * sens_df$Shift_Cont[6])` pp at S6, which is `r sprintf("%.0f", 100 * (1 - sens_df$Shift_Cont[6] / sens_df$Shift_Cont[best_row]))`% below the best row. Under this standardized shift the gradient looks moderate (the best row is about `r sprintf("%.1f", sens_df$Shift_Cont[best_row] / sens_df$Shift_Cont[6])` times the last). The next table shows that this depends on how the perturbation is defined, and the ranking check in [Parameter Uncertainty](#parameter-uncertainty-dirichlet) shows that the order of the top two rows is not stable. Two caveats: the 0.05 shift is a different relative change in each row, and the table only covers attacks that start at S1. The ranking reflects the hand-set parameters.

**Why the ranking looks this way.** For a small shift $\varepsilon$ from edge $(i, j)$ to A1, the change in containment from S1 is approximately

$$\Delta B_{1,A1} \approx \varepsilon \, N_{1i} \, \bigl(1 - B_{j,A1}\bigr)$$

That is, expected visits to row $i$ times the catastrophic share of the donor state $j$. The table below confirms that the identity reproduces the standardized-shift column. The modest gradient is the product of two opposing trends: visits fall with depth while the donor's catastrophic share rises. It also depends on the perturbation design.

A defensible ranking needs a control-to-parameter mapping, ideally expressed as hazard ratios on rates. A fixed absolute shift is not enough.

## Parameter Uncertainty (Dirichlet) {#parameter-uncertainty-dirichlet}

Closed-form results are exact only **given** $P$, and $P$ is uncertain. To quantify that, each transient row is treated as Dirichlet($\alpha \cdot p_{\text{row}}$) over its non-zero entries (structural zeros stay zero), with concentration $\alpha = 50$ as a stand-in for "moderate confidence" in the elicited values. The solver is re-run on 5,000 sampled matrices per regime.

It is largest for attacks starting at `r sub(":.*", "", paired_summary$Stage[which.max(paired_summary$med)])`. Even so, both postures are hand-set scenarios, not measured controls, so this shows how much difference such a change in assumptions makes, not what a specific security investment would deliver.

**The scenario effect has a meaningful interval.** Drawing both regimes from the same random numbers (common random numbers through the gamma quantile function) isolates the scenario difference from parameter noise. The S1 containment uplift is `r pp1(paired_summary$med[1])`, with a 90% interval of `r pp1(paired_summary$lo[1])`–`r pp1(paired_summary$hi[1])`. This is still a difference between two hand-set matrices, not a measured control effect.

### Robustness of the One-Row Ranking

**The one-row ranking is not robust.** Repeating the standardized 0.05 shift on `r format(n_rank, big.mark = ",")` Dirichlet draws, the S2 row gives the largest containment gain from S1 in `r pct1(p_best_s2)` of draws and the S1 row in `r pct1(p_best_s1)`; S2 beats S1 in `r pct1(p_s2_beats_s1)` of draws. ## Limitations and Future Work {#limitations}

The model's structural assumptions are listed under [Parameterization and Assumptions](model.qmd#parameterization-and-assumptions), and the sections above show how sensitive the results are to the elicited inputs. This section covers the data a richer, calibrated version would need.

### Future work: real-world data sources

The current model uses none of the following sources. They describe network and identity topology, which tells a richer model which edges exist. They do not by themselves supply the transition probabilities or timing this model needs (see the calibration note after the table).

**Network Telemetry & Flow Logs:** Real connection edges and service dependencies come from VPC Flow Logs (AWS/Azure/GCP), Zeek/Corelight network analysis sensors, and NetFlow/IPFIX from core network routers and firewalls.

**Service Dependency & Configuration Management Databases (CMDB):** Service-to-service call maps are extracted from application performance monitoring tools (e.g., Datadog, Dynatrace), service mesh registries (e.g., Istio, Envoy), and enterprise CMDBs (e.g., ServiceNow).

**Vulnerability Management & Posture Assessment Scanners:** CVSS scores, exploit metrics, and missing patches are pulled via API from enterprise vulnerability scanners such as Tenable Nessus, Qualys, Rapid7 InsightVM, or cloud posture platforms (Wiz, Prisma Cloud).

**Active Directory & Identity Access Graphs:** Identity edges and lateral movement pathways are exported from tools like BloodHound Enterprise, Microsoft Entra ID, and Okta Access Graph logs.

Obtaining this type of accurate data at scale is not easy:

### Calibration Data and Survival-Analysis Pitfalls

The parameters of this model are stage-transition probabilities and stage durations. Estimating them requires timestamped transitions rather than topology:

-   Internal incident-response timelines and EDR or SIEM alert timestamps mapped to MITRE ATT&CK tactics.
-   Purple-team and breach-and-attack-simulation results (time to detect per technique).
-   The VERIS Community Database, whose timeline fields record initial compromise, exfiltration, discovery, and containment in coarse units ([VERIS Framework](https://verisframework.org/discovery.html)).
-   Public benchmarks as priors: M-Trends, the Sophos Active Adversary Report, and CrowdStrike breakout times.

Fitting these data raises standard survival-analysis issues:

-   **Right censoring:** incidents still open at data extraction.
-   **Interval censoring:** stage entry is known only to a window, or to a unit such as "days."
-   **Left truncation and detection-dependent selection:** only detected intrusions are recorded.
-   **Competing risks:** containment censors progression, so naive Kaplan–Meier estimates of time to catastrophe are biased, and Aalen–Johansen estimators are appropriate.
-   **Unobserved heterogeneity:** attacker types differ, for example fast eCrime affiliates versus slow espionage actors.

Multi-state packages such as `msm`, `mstate`, and `flexsurv` handle these directly.
